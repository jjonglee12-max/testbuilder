# AI Blog Studio

서버 없이 사용하는 Electron 데스크톱 블로그 편집 앱입니다. React 화면에서 원고를 만들고 사람이 특정 버전을 승인한 뒤 WordPress/Blogger API로 공개 발행합니다.

## Windows 앱 다운로드

저장소의 **Releases**에서 최신 Windows 개발 버전을 열고 **Assets**의 `*-win.zip` 파일을 받으세요. `Source code`는 실행용 ZIP이 아닙니다. 모두 압축 해제한 뒤 `AI Blog Studio.exe`를 실행합니다.

`main`에 코드를 올리면 GitHub Actions의 **Build Windows app**이 테스트·빌드 후 Releases에 다운로드 파일을 게시합니다. 진행 상황은 저장소 **Actions** 탭에서 확인합니다. GitHub Actions가 꺼져 있으면 저장소에서 먼저 활성화해야 합니다. 이 개발 버전은 코드서명되지 않았습니다.

## 실행

Node.js 22.12 이상 또는 24 LTS를 사용합니다.

```bash
npm ci
npm run desktop
```

브라우저에서 화면만 확인하려면 `npm run dev`를 사용합니다. 브라우저 모드는 원고를 localStorage에 저장하며 인증정보 저장·AI 호출·승인·발행은 하지 않습니다. 브라우저와 데스크톱 데이터는 공유되지 않습니다.

Windows에서 배포 파일을 만들려면:

```bash
npm run package:win
```

결과는 `release/`에 생성됩니다. Linux에서 Windows ZIP 생성과 패키지 내용은 검증했습니다. Windows에서 실행 검증은 아직 하지 않았습니다. ZIP을 모두 압축 해제한 뒤 `AI Blog Studio.exe`를 실행하세요. 코드서명은 구성하지 않았습니다.

## 사용 순서

1. 사이트 관리에서 사이트와 인증정보를 추가합니다.
2. 연결 확인으로 읽기 접근을 확인합니다. 게시 권한 검증과는 다릅니다.
3. AI·프롬프트에서 OpenAI 호환 API 주소·모델·키를 저장합니다. API 사용료는 사용자가 연결한 서비스에 따릅니다.
4. 사이트별 주제·독자·말투·추가 편집 지침을 저장합니다. 자료함에서 URL 본문을 수집하거나 직접 참고 메모를 작성합니다.
5. 새 글에서 글쓰기 기준 사이트와 자료(최대 8개)를 선택하고 초안을 생성합니다. URL만 메모에 붙여넣으면 자동 수집하지 않으므로 수집 버튼을 사용하세요.
6. 이미지 탭에서 파일 또는 호스팅한 이미지 URL, 대체 텍스트·캡션을 설정합니다. 발행 방식·예약 시각을 정합니다.
7. **별도 AI 검토 실행**으로 지적 사항과 사실 목록을 확인합니다. AI 초안은 이 단계를 거쳐야 합니다.
8. 사람이 미리보기·출처·검토 결과를 확인하고 승인합니다. 검토 후 원고·자료·운영 설정이 변경되면 재검토합니다. 직접 작성한 원고는 AI 검토 없이 수동 확인해 승인할 수 있습니다.
9. 즉시 발행 또는 승인한 원고 예약 등록을 누르고 대상 사이트·시간을 확인합니다.

### WordPress

자체 호스팅 WordPress의 HTTPS REST API와 Application Password를 사용합니다. 사용자 프로필에서 발급한 애플리케이션 비밀번호와 해당 사용자명을 입력하세요. WordPress.com OAuth 연결은 지원하지 않습니다. 설치 경로가 하위 디렉터리인 경우 해당 경로까지 사이트 주소에 입력합니다.

### Blogger

Google Blogger API의 `https://www.googleapis.com/auth/blogger` 권한이 있는 OAuth 액세스 토큰과 숫자 블로그 ID를 사용합니다. 수동 토큰 방식이며 로그인·refresh token 갱신 기능은 아직 없습니다. 만료 시 사이트 ‘수정’에서 토큰을 교체하세요.

### AI

OpenAI 호환 `/chat/completions` API의 JSON 응답 모드를 사용합니다. 모든 공급자가 이 형식을 지원하지는 않습니다. API 기본 주소는 `/v1`까지 입력하며 `/chat/completions`는 앱이 붙입니다. 주제와 참고 자료가 설정한 공급자에게 전송됩니다. 로컬 Codex CLI 로그인 연동은 0.6.0에서 별도 작업 엔진으로 추가했습니다. API 방식은 계속 별도의 키와 과금 체계를 사용합니다.

## 데이터와 발행 보호

- 원고·사이트·설정·작업 로그는 Electron `userData`의 `studio.json`에 저장합니다. 파일 기록은 임시 파일 후 이름 변경 방식입니다.
- 첫 버전은 JSON 저장소를 사용하며 SQLite 마이그레이션은 후속 범위입니다. 원고·참고 자료는 평문 로컬 데이터입니다.
- API 키·사이트 인증정보는 Electron safeStorage로 암호화합니다. 운영체제 보안 저장소가 없거나 Linux basic_text 방식이면 저장을 거부합니다. 렌더러에 인증정보를 돌려주지 않습니다.
- 승인 지문은 제목·본문·발행 사이트와 연결 설정을 포함합니다. 내용이나 대상 변경 시 이전 승인은 유효하지 않습니다.
- 성공한 글은 중복 발행을 차단하고 기록을 보존합니다. 새 글은 복사해서 작성하고, 기존 게시물 수정은 0.5.0의 별도 수정본 흐름을 사용합니다.
- 발행 요청이 실패하거나 결과를 확정할 수 없으면 `uncertain` 상태로 두고 자동 재시도를 차단합니다. 사이트 관리자에서 실제 게시 여부를 확인한 뒤 발행 주소를 기록하거나 미발행 상태로 돌립니다.
- 앱 종료 중 발행이 진행 중이었다면 재시작 시 결과 확인 상태로 전환합니다.
- 편집기와 발행기는 동일한 단순 서식을 사용합니다. `#`~`###` 제목, 빈 줄로 구분한 문단과 줄바꿈을 지원하며 원고 HTML은 이스케이프합니다. 이미지 탭에서 본문 위·아래 이미지와 대표 이미지를 설정합니다. 본문의 HTTPS URL은 발행 시 링크로 변환합니다. 완전한 Markdown과 문단 사이 이미지 삽입은 아직 지원하지 않습니다.

## 현재 범위와 남은 작업

구현: 대시보드, 원고 보관·검색, 편집·미리보기, AI 초안 API 연결, 프롬프트 수정·저장, 사이트 저장·수정·읽기 연결, 승인과 실제 즉시 발행 경로, 발행 결과 기록과 수동 복구.

미구현: 상품 수집 확장, AI 이미지 생성, Blogger 파일 업로드, 검색 엔진 자동 탐색, 전체 프롬프트 원문 이력, SQLite, Blogger 자동 OAuth 로그인.

기본 프롬프트는 `prompts/ai-blog-v1.md`입니다. 편집 기준과 제품 구현 범위를 혼동하지 않도록 앱이 아직 하지 않는 작업은 완료했다고 표시하지 않습니다. 생성 시 모델 ID·프롬프트 해시·시각과 AI 자기 보고 메모를 원고에 기록합니다. 작성 메모와 별도 검토 결과는 구분해 저장합니다. 별도 AI 검토는 제공된 자료 범위의 대조이며 독립적인 사실 보증이나 외부 검색 검증은 아닙니다.

## 검증

```bash
npm test
npm run build
```

승인 누락·본문/대상 변경·중복 발행·결과 불확실 상태·HTML 이스케이프·HTTPS 검증과, 모의 Electron/HTTP 환경의 저장→승인→발행→오류 복구를 검사합니다. 실제 계정으로 게시하거나 API 과금을 발생시키는 검증은 포함하지 않습니다.

클라우드에서 의존성 설치 시 프록시가 필요하면 `NODE_USE_ENV_PROXY=1`을 사용하고, 쓰기 가능한 캐시 경로를 설정합니다. TLS·체크섬 검증은 유지합니다.

## 0.1.1 변경

AI 설정에서 모델 목록을 조회하고 **연결 테스트 후 저장**으로 실제 생성 응답을 확인할 수 있습니다. 테스트는 소액 API 사용료가 발생할 수 있으며 실행 전에 확인합니다. 키를 저장한 것만으로 연결 성공으로 표시하지 않습니다. 주소를 다른 공급자로 변경하면 키를 다시 입력해야 합니다. 워크스페이스 카드를 누르면 이름을 변경하고 저장할 수 있습니다. 현재 하나의 로컬 작업 공간을 제공하며 다중 워크스페이스 분리는 아직 지원하지 않습니다.

## 0.2.0: 자료와 편집·검토 흐름

- 사이트마다 주제·독자·말투·추가 편집 지침과 편집용 분류를 저장합니다. 생성과 검토에 동일한 설정을 전달하고, 생성 시점의 설정도 원고에 기록합니다. 편집용 분류를 원격 WordPress 카테고리나 Blogger 라벨로 자동 등록하지는 않습니다.
- 자료함과 편집기에서 공개 HTTPS URL을 1~5개씩 수집합니다. JavaScript를 실행하지 않고 HTML/텍스트 본문을 읽습니다. 로그인·PDF·동적 렌더링 페이지는 직접 참고 메모로 추가하세요. 출처 URL·열람 시각·본문·내용 해시를 저장하며, 같은 URL의 내용이 바뀌면 새 자료 버전으로 보관합니다.
- 수집 크기는 페이지당 1.5MB, 저장 본문은 24,000자, 원고에 연결할 자료는 최대 8개입니다. 일부 본문만 저장되면 표시합니다. 일부 URL이 실패해도 성공한 자료는 보존합니다.
- 자료 수집에는 로그인 세션·API 키를 전달하지 않습니다. 공개 IP를 확인하고 고정해 요청하며 이동한 주소도 다시 검사합니다. 사설·로컬 주소와 비HTTPS·비표준 포트는 거부합니다. 회사 프록시·VPN 전용 자료 수집은 지원하지 않습니다.
- 별도 AI 검토는 새 모델 호출입니다. 제공한 자료와 원고를 대조해 차단·주의·제안, 사실 목록과 출처 ID, 검토 모델·시각을 저장합니다. 생성과 검토 모두 API 사용료가 발생할 수 있습니다.
- AI 초안은 검토 전 승인할 수 없습니다. 차단 지적·자료와 불일치한 사실이 있으면 수정 후 재검토합니다. 사람이 작성한 원고는 수동 검토할 수 있습니다. AI 검토 통과만으로 자동 승인·발행하지 않습니다.
- 제목·본문·메모·선택 자료·사이트 편집 기준 변경 시 검토 지문이 달라집니다. 검토 도중 원고가 바뀌면 응답을 덮어쓰지 않습니다. 수정 전 검토는 오래된 결과로 남깁니다.
- 검증: 모의 네트워크/Electron 환경에서 수집 부분 실패·중복 제거·자료 버전 보관·사이트별 생성·별도 검토·수정 필요 차단·동시 변경·설정 변경을 확인합니다. 공식 Node.js HTML의 본문 추출도 확인했습니다. 이 클라우드의 직접 DNS 조회 제약으로 실제 DNS→HTTPS 수집 전체 경로는 Windows에서 추가 확인이 필요합니다. 실제 유료 AI·블로그 계정 호출은 수행하지 않았습니다.

## 0.3.0: 이미지와 예약 발행

### 이미지

- 원고의 이미지 탭에서 PNG·JPEG·WebP 파일을 가져옵니다. 파일당 10MB·4천만 화소 이하, 원고당 10장, 로컬 보관은 100개까지 지원합니다. 파일과 썸네일은 Electron userData에 저장하며 원본 경로에 의존하지 않습니다.
- 대체 텍스트는 필수입니다. 캡션·본문 위/아래 배치·순서를 수정하고, 로컬 파일 한 장을 WordPress 대표 이미지로 지정하고 본문에서는 빼는 옵션도 사용할 수 있습니다. 원고에서 제거해도 보관 파일이나 이미 업로드한 원격 미디어는 자동 삭제하지 않습니다.
- WordPress 발행 시 `/wp-json/wp/v2/media`에 업로드하고 alt_text·caption·featured_media를 적용합니다. 이미지 업로드 권한이 필요합니다. 같은 이미지의 업로드 결과를 사이트별로 재사용합니다. 업로드를 시도했다가 응답을 잃으면 원격 미디어가 남을 수 있지만, 게시 요청 전 실패라면 글을 중복 게시하지 않고 재시도할 수 있습니다.
- Blogger에는 이미지 업로드 API가 없으므로 기존에 호스팅한 HTTPS 이미지 URL을 입력합니다. 로컬 파일이 연결된 Blogger 원고는 승인할 수 없습니다. 외부 이미지는 앱에서 자동 다운로드하지 않으며 실제 표시·접근 권한·이용 조건은 사람이 확인합니다.
- AI 검토에는 이미지 픽셀을 보내지 않고 대체 텍스트·캡션을 전달합니다. 이미지 내용을 직접 검증하는 기능이나 AI 이미지 생성 기능은 아닙니다.

### 예약

- **플랫폼 예약**: WordPress는 `status=future`·`date_gmt`로 등록합니다. 사이트의 WP-Cron/서버 설정에 따라 실행이 늦어질 수 있습니다. Blogger는 초안을 만들고 `posts.publish`의 `publishDate`로 예약합니다. 등록 성공 후에는 앱이나 PC를 꺼도 됩니다. API에 예약 상태가 확인된 경우에만 등록 완료로 표시합니다.
- **로컬 예약**: 승인한 원고를 로컬 대기열에 넣습니다. PC와 앱이 켜져 있고 인터넷에 연결돼 있어야 합니다. 약 15초 간격으로 확인하며 5분 넘게 늦으면 보류합니다. 앱을 다시 켰을 때 이미 지난 예약은 즉시 발행하지 않고 보류합니다. 한 앱 인스턴스만 실행해 중복 대기열 처리를 막습니다.
- 예약 입력·목록 시간은 한국 시간(UTC+9)이며 저장/API 전송은 UTC입니다. 최소 1분 뒤로 예약합니다. 발행 일정 화면에서 등록 결과·실패·보류를 확인합니다. 플랫폼 등록은 발행 완료를 의미하지 않으며 **플랫폼 상태 조회**로 게시 여부를 확인합니다.
- 예약을 등록한 원고는 편집할 수 없습니다. 먼저 예약을 해제하세요. 플랫폼 예약 취소는 원격 글을 초안으로 돌리며 삭제하지 않습니다. 발행 2분 전부터는 경합을 줄이기 위해 앱에서 취소하지 않고 플랫폼 관리자에서 직접 취소하도록 안내합니다.
- 예약·이미지·제목·본문·대상 사이트는 최종 승인에 포함됩니다. 예약 시각만 바꾸면 사람 재승인은 필요하지만 AI 내용 검토는 다시 호출하지 않아도 됩니다. 이미지 정보 변경은 재검토 대상입니다. 이전 버전에서 저장한 승인은 새 버전에서 재확인해야 할 수 있습니다.
- 발행·예약 등록·취소 결과가 불확실하면 자동 재시도하지 않습니다. 원격 ID가 있으면 플랫폼 상태를 조회하고, 없으면 사이트 관리자에서 직접 확인합니다. 취소한 원격 초안과 업로드한 미디어는 자동으로 정리하지 않습니다.

### 확인 범위

모의 API로 WordPress 이미지·대표 이미지·UTC 예약·취소, Blogger 초안 생성→예약·취소, 로컬 예약의 단일 발행·재시작·시간 경과 보류, 이미지 준비 실패·게시 결과 불확실 시 재시도 차단을 검사합니다. 실제 계정 업로드·예약 시각의 실발행·WordPress 서버 크론 동작은 사용자 환경에서 확인해야 합니다. 사용자 수동 테스트는 기능 추가 후 한 번에 진행할 수 있습니다.

공식 API 참고: https://developers.google.com/blogger/docs/3.0/reference/posts/publish 및 https://developer.wordpress.org/rest-api/reference/posts/ , https://developer.wordpress.org/rest-api/reference/media/

## 0.4.0: 발행 분류·기존 글·주제 기획과 일괄 준비

### 실제 발행 분류

- 원고의 실제 발행 분류에서 WordPress 카테고리·태그를 조회하고 기존 ID를 선택합니다. 각 목록은 최대 500개입니다. 선택한 ID가 실제 발행·예약 요청의 categories/tags에 포함됩니다. 미선택 시 카테고리는 WordPress 기본값을 사용합니다. 새 분류를 만드는 기능은 없으며 사이트 관리자에서 추가한 뒤 다시 불러옵니다.
- Blogger 라벨은 쉼표로 입력하며 새 라벨도 게시물에 적용할 수 있습니다(각 100자, 최대 20개). 기존 라벨 제안은 가져온 공개 게시물에서 모으므로 전체 라벨 목록을 보장하지 않습니다. 최초 분류 조회 시 게시물 첫 페이지를 함께 읽어 제안을 준비합니다.
- 사이트 연결이 바뀌면 이전 분류 ID를 그대로 쓰지 않고 다시 조회하도록 합니다. 분류 변경은 최종 재승인이 필요하지만 내용 AI 검토는 재사용할 수 있습니다. 기존 버전의 승인·검토는 새 버전에서 재확인이 필요할 수 있습니다.

### 기존 글과 내부 링크

- 기존 발행 글에서 공개 게시물의 제목·URL·날짜·분류를 100개씩 가져옵니다. WordPress 요약문도 보관합니다. 다음 페이지 버튼으로 이어서 읽고, 처음부터 새로 불러오면 해당 사이트의 로컬 글 목록 캐시를 새로 채웁니다. 원격 본문이나 로컬 원고를 덮어쓰지 않습니다.
- HTTPS URL 형식이 맞지 않는 기록은 제외합니다. 기본 blogspot.com의 HTTP URL은 HTTPS로 정규화합니다. 링크 대상의 현재 접근 가능 여부·삭제 여부까지 검증하는 것은 아닙니다. WordPress 일반 posts와 Blogger LIVE 게시물이 대상이며 페이지·비공개·예약 글은 가져오지 않습니다.
- 내부 링크·유사 글 찾기는 같은 사이트의 불러온 목록과 제목·키워드를 비교합니다. 실제 URL만 후보로 보여주며, 선택하면 원고 끝에 Markdown 링크를 넣습니다. 원하는 문단으로 이동해 검토하세요. 링크를 넣으면 본문이 바뀌므로 재검토·재승인 대상입니다.
- 생성 AI에도 관련 기존 글의 실제 제목과 URL을 참고 자료로 전달합니다. 키워드 매칭 기반 추천과 중복 경고는 완전한 의미 중복 검사나 SEO 성과 보증이 아닙니다.

### 주제 기획 · 콘텐츠 캘린더

- 사이트·주제·글 유형·참고 URL·메모·보관 자료·분류·작성 예정일을 등록합니다. 주제를 줄마다 넣어 한 번에 최대 20개를 공통 자료로 등록할 수 있습니다. 주제별 자료가 다르면 개별 기획에서 수정하세요.
- 달력 날짜는 작성 계획이며 발행 예약이 아닙니다. 기획·준비 중·검토 대기·수정 필요·실패·중단 상태를 날짜와 사이트별로 확인합니다.
- 기존 발행 글·로컬 원고·다른 기획과 유사한 주제는 경고합니다. 경고가 있으면 기획에서 허용 여부를 확인해야 준비를 시작합니다. 기획의 내용·자료를 바꾸면 새 초안을 준비하며 이전 원고는 지우지 않습니다. 기획 삭제도 원고를 삭제하지 않습니다.

### 여러 원고 일괄 준비

- 기획을 1~20개 선택해 참고 자료 수집 → 초안 생성 → 별도 AI 검토를 순서대로 실행합니다. 참고 URL·자료·메모 중 하나는 필요합니다. 앱이 실행 중이어야 합니다. 실행 전에 최대 주제당 2회의 AI 호출과 API 비용 안내를 확인합니다. 승인·이미지 준비·예약·발행은 자동 실행하지 않습니다.
- 각 단계의 상태와 원고를 저장합니다. 참고 자료 수집 실패는 해당 기획에 남기고 후속 기획을 처리하며, AI 작성·검토 오류가 발생하면 후속 유료 작업을 중지합니다. 중지 버튼은 이미 보낸 요청을 취소하지 않으며 현재 단계 완료 후 멈춥니다. 진행 중인 요청은 비용이 발생할 수 있습니다.
- 검토 실패·중단 후 다시 선택해 실행하면 변경되지 않은 저장 초안은 재사용하고 검토부터 이어갑니다. 기획 내용이나 자료가 바뀌면 기존 원고를 보존한 채 새 초안을 준비합니다. 앱 재시작 시 중단된 유료 작업은 자동 재개하지 않습니다. 마지막 요청의 비용이 발생했을 수 있으므로 진행 기록을 먼저 확인하세요.
- 준비 중인 원고는 편집·승인할 수 없습니다. 진행 중에는 AI 연결·공통 프롬프트·사이트 설정 변경과 사이트 목록 새로고침을 막아 중간 설정 혼합을 방지합니다. 완료한 원고는 원고별로 열어 확인·승인·예약할 수 있습니다. 일괄 승인 기능은 없습니다.
- 초안 준비 자체에는 블로그 발행 인증이 필요하지 않습니다. 기존 글·분류 조회와 실제 발행에는 해당 사이트의 사용 가능한 인증이 필요합니다. AI 연결은 준비 단계부터 필요합니다.

권장 순서: 사이트 연결 → 분류·기존 글 조회 → 주제 기획·자료 등록 → 선택한 주제 준비 → 원고별 내부 링크·이미지 수정 → 검토·사람 승인 → 예약 또는 즉시 발행.

검증: 모의 WordPress/Blogger 응답으로 분류 필드 발행, 페이지 이동, 라벨 제안, 실제 링크 추천, 일괄 중지·재개·초안 재사용·중단 복구·중복 경고·자동 승인/발행 차단을 확인합니다. 브라우저에서는 테스트용 브리지로 화면 흐름을 확인합니다. 실제 계정 조회·유료 AI 호출·실발행은 사용자 환경에서 추가 확인해야 합니다. 사용자 수동 테스트는 기능 추가 후 모아서 진행할 수 있습니다.

## 0.5.0: 백업·변경 이력·기존 글 수정

- **백업 · 복원**: 로컬 수동 백업과 외부 폴더 내보내기, 백업 폴더 선택 후 병합 복구를 지원합니다. ZIP이 아니라 `manifest.json`, `state.json`, `media/`, `history/`가 든 폴더 전체를 보관합니다. 실행한 날짜의 첫 시작에 일일 백업하며 로컬 백업 폴더는 자동 정리 시 최근 10개를 유지합니다. 원격 글 수정·복구 전에도 백업을 만듭니다.
- API 키·사이트 비밀번호는 백업에서 제외합니다. 원고·자료·이미지는 평문입니다. 새 PC에서는 인증정보를 다시 입력합니다. 체크섬은 손상 감지용이며 출처 인증이나 암호화가 아닙니다.
- 복구는 현재 원고를 유지하고 복구본을 추가하며 승인·검토를 해제합니다. 로컬 예약과 유료 작업은 재개하지 않습니다. 원격 플랫폼의 예약·게시물은 복구로 취소되거나 되돌아가지 않습니다. 발행 중·일괄 준비 중·로컬 예약 실행 대기 중에는 먼저 작업을 중지해야 합니다.
- **변경 이력**: 저장 전후 버전을 원고별 최근 20개, 전체 최근 500개 보관합니다. 줄 위치 기준 비교와 로컬 복원을 지원합니다. 발행 완료 원고는 새 복원본을 만들며, 기존 글 수정본의 이력 복원은 최신 원격 원문을 읽어 새 수정본을 준비합니다. 원고 삭제 후에도 보관 한도 내의 이력에서 복원할 수 있습니다.
- **기존 발행 글 → 이 글 수정본 만들기**: 편집 권한으로 원문 HTML을 불러와 로컬 수정본을 만듭니다. 수동 편집 또는 요청에 따른 AI 수정안 → 원문 비교 → AI 생성분 별도 검토 → 사람 승인 → **기존 글에 수정 반영** 순서입니다. AI 요청 시 원문과 자료가 설정한 공급자에 전송되며 호출 전에 확인합니다.
- 수정은 동일 게시물 ID에 제목·본문·분류만 보내며 발행일·공개 상태·대표 이미지 필드를 보내지 않습니다. 플랫폼이나 플러그인이 자동 변경하는 값까지 보장하지는 않습니다. 일반 HTML·블록 주석은 보존하고 스크립트·iframe 등 실행 가능한 임베드 글은 지원하지 않습니다. HTML 수정본은 이미지 탭과 예약 대신 원문 URL 편집·즉시 반영을 사용합니다.
- 반영 직전 원격 원문을 다시 비교하고 ETag 등 조건부 갱신 헤더를 사용합니다. 충돌하면 최신 원문으로 새 수정본을 만들어야 합니다. WordPress 등 서버가 조건부 헤더를 적용하지 않는 경우 조회와 쓰기 사이의 짧은 경합을 완전히 차단할 수는 없습니다. 결과가 불확실하면 자동 재시도 없이 **기존 글 수정 결과 조회**로 확인합니다.

검증: 60개 자동 검사 통과(기존 검사 포함), 프로덕션 화면 빌드, 모의 데이터 기반 브라우저의 기존 글 열기·HTML 비교·승인·수정 반영·이력 복원·백업 화면 흐름을 확인했습니다. 실제 블로그 수정·유료 AI·Windows 폴더 선택 대화상자 실행은 포함하지 않았습니다.

## 0.6.0: 로컬 Codex 연결과 자연어 작업실

**Codex CLI는 앱 ZIP에 포함되지 않으며 사용자의 PC에 별도로 설치해야 합니다.** 최신 CLI가 제공하는 `exec --ignore-user-config --ignore-rules --ephemeral --json --output-schema` 실행 옵션을 확인합니다. 오래된 CLI에서는 연결을 거부하고 업데이트 안내를 표시합니다.

1. [공식 Codex CLI 안내](https://developers.openai.com/codex/cli/)에 따라 설치합니다. Node.js 환경이면 터미널에서 `npm install -g @openai/codex`를 사용할 수 있습니다.
2. 같은 OS 사용자 계정의 터미널에서 `codex login`을 실행합니다. 필요한 경우 `codex login --device-auth`를 사용합니다. 로그인은 CLI가 처리하며 앱은 토큰·auth.json을 읽거나 복사하지 않습니다.
3. 앱을 다시 열고 **Codex 작업실 → 설정 저장·연결 확인**을 누릅니다. 설치·필수 실행 옵션·로그인 상태만 확인하며 모델 요청을 보내지 않습니다. 실행 파일 경로를 비우면 PATH와 npm 설치 위치에서 탐색하고, Windows에서는 `.cmd`를 실행하지 않고 패키지의 실제 `codex.exe`를 찾습니다. 실패하면 **실행 파일 선택**으로 지정합니다.
4. **작업 엔진 → 로컬 Codex**를 선택하면 기존 초안 생성·별도 검토·기존 글 AI 수정·여러 주제 준비도 Codex를 사용합니다. 기존 AI API 설정은 유지하며 API로 다시 전환할 수 있습니다. Codex 실행 실패 시 API로 자동 전환하거나 유료 요청을 재시도하지 않습니다.
5. **Codex에게 작업 요청**에서 사이트 편집 기준·보관 자료(최대 8개)·선택한 참고 원고와 자연어 요청으로 주제 제안·조사·작성·개선을 실행합니다. 웹 검색은 연결 설정에서 허용하고 해당 작업에서도 선택해야 켜집니다. 기존 생성·검토·수정·일괄 준비에서는 보관 자료만 사용합니다.
6. 결과의 주제는 기획에 추가할 수 있고, 완성 초안은 **새 원고로 가져오기**로 명시적으로 저장합니다. 참고 원고는 덮어쓰지 않습니다. 제시한 URL은 수집·검증된 자료로 표시하지 않습니다. 자료함에서 직접 수집하고 별도 검토에 연결하세요.

한 번에 하나의 Codex 작업을 실행하며 다른 화면에서도 진행 표시·중지가 가능합니다. 15분 초과·인증 오류·응답 형식 오류·취소는 결과를 가져오지 않고 끝냅니다. 중지 또는 앱 종료 전에 사용한 이용량은 발생했을 수 있습니다. 앱 재시작 시 진행 중 작업은 중단 상태로 표시하며 재개하지 않습니다. 작업실은 마지막 작업 결과를 보여주므로 다음 요청 전에 필요한 원고를 가져오세요.

실행은 셸 문자열 대신 인자 배열·stdin을 사용합니다. 별도 임시 작업 폴더, 읽기 전용 sandbox, 개인 CLI 설정·프로젝트 지침 제외, 셸·MCP·앱·플러그인·하위 에이전트 기능 제외 설정으로 편집 작업을 제한합니다. 앱의 블로그 비밀번호·API 키는 프롬프트와 프로세스 환경에 전달하지 않습니다. CLI 자체의 로그인은 CLI가 사용합니다. 모델이 발행 도구를 받지 않으며, 앱의 발행 인증과 사람 승인을 대신할 수 없습니다.

Codex 이용 한도·요금은 CLI가 로그인한 계정과 선택 모델에 따릅니다. 기본 모델을 비워두면 CLI 기본 모델을 사용하며 앱은 이를 특정 모델로 표시하지 않습니다. 표시하는 입력·출력 토큰은 CLI가 보고한 사용량이며 요금이나 남은 구독 한도 계산이 아닙니다. API 방식과 Codex 로그인 방식의 결제를 합산하거나 구독 혜택을 보장하지 않습니다.

백업에는 가져와 저장한 원고·검토 기록을 포함합니다. Codex 실행 경로·로그인·일회 작업 결과는 다른 PC로 내보내지 않으므로 새 PC에서 CLI를 다시 연결하세요. 아직 가져오지 않은 작업실 결과는 백업 대상이 아닙니다.

검증: 로컬 Codex CLI 0.163.0의 설치·기능·로그인 상태 조회, 모의 CLI 자식 프로세스를 통한 실행·중지·시간 초과·인증 실패·스키마 검증, Electron IPC에서 API 키 없는 생성·별도 검토·수정 제안·일괄 준비·결과 가져오기, 브라우저에서 연결 설정·엔진 변경·검색 선택·진행 표시·가져오기·중지 흐름을 확인했습니다. 실제 유료 Codex 생성과 실제 블로그 발행, Windows 사용자 PC의 로그인·sandbox 동작은 추가 확인이 필요합니다.
